# 辦公室心動日常 — MVP 規格書

> 關聯文件：[docs/script/day1.md](script/day1.md)（第一天劇本大綱）、[docs/design/ui-direction.md](design/ui-direction.md)（UI 方向）

## 1. 目標

做出一個能玩完「一天」的網頁原型，用來驗證一件事：**一天的流程好不好玩。**

### 成功標準
- 玩家從 09:00 玩到 18:00，一輪約 **10–15 分鐘**。
- 找 3–5 位朋友試玩，觀察並記錄：
  - 玩完後會不會主動問「有第二天嗎？」或想再玩一次走另一條線。
  - 「預判主管」小遊戲的難度：太簡單、剛好、還是太難。
  - 對主管的反應是笑，還是覺得不舒服。不舒服就調低他的台詞強度。
- 全程只用鍵盤或只用滑鼠都能玩完。

## 2. 範圍

### 包含（MVP）
- 1 天劇情，分成 5 個時段。
- 2 位男角，用佔位圖（色塊加名字）。
- 1 位主管，3 種出現模式：巡邏、突襲、回馬槍。
- 好感度（每位男角各一個數值）。
- 懷疑值（被抓次數）。
- 「預判主管」掩護小遊戲。
- 2 種結局：平安下班（依好感度較高的男角給不同文字）、被抓搞笑結局。
- 對話框、選項、時鐘、主管警報、結局卡等 UI。

### 不包含（以及原因）
| 不做 | 原因 |
| --- | --- |
| Three.js、3D | 2D 遊戲用不到，只會增加成本。 |
| Roguelike 隨機循環 | 內容量不夠會很快重複，先做線性劇情。 |
| 工作倒數系統 | 會讓遊戲變成辦公室模擬，稀釋主題。 |
| 男角各自的躲藏技能 | 先把共通機制做好。 |
| 明確成人內容 | 維持曖昧心動向。 |
| 多人連線 | 單人遊戲。 |
| 美術成品、AI 生圖 | 先用佔位圖確認玩法成立。 |
| 音效配樂、存檔、多日劇情 | 不在本次驗證範圍。 |

## 3. 角色（佔位設定，可隨時替換）

| 角色 | 設定 | 說話方式 |
| --- | --- | --- |
| **林晏晴**（女主，玩家化身） | 28 歲，資深企劃。能力很強，卻被主管壓榨。偷情是她唯一的樂趣，也是小小的反抗。 | 表面專業有禮，內心吐槽很多。內心獨白用另一種樣式顯示。 |
| **周以澄**（男角 A） | 24 歲，新進工程師。年下忠犬系，直球、容易臉紅。 | 叫她「晏晴姐」，句尾常帶驚嘆號。 |
| **沈硯**（男角 B） | 31 歲，法務。冷淡系，嘴冷手暖。 | 句子短，不用語助詞，偶爾一句很重的話。 |
| **賈正經**（主管，經理） | 地中海，自以為幽默，永遠在吃茶葉蛋。 | 口頭禪：「我們是一家人嘛」「這個很簡單吧？下班前給我」。 |

**主管的分寸：** 他好笑、煩人、愛搶功、愛丟工作，但**不做性騷擾，也沒有肢體冒犯**。他的噁心是「愛講幹話、身上有茶葉蛋味」這一類。

## 4. 核心循環

```
開場 → [時段 1..5]：對話 → 選項（加減好感）→ 主管事件（若有）→ 下一時段 → 結局判定
```

| 時段 | 地點 | 主要男角 | 主管模式 |
| --- | --- | --- | --- |
| 09:00 | 晨會後的座位區 | 周以澄 | 巡邏（教學關） |
| 10:30 | 茶水間 | 沈硯 | 突襲 |
| 12:30 | 午休頂樓 | 玩家二選一 | 無（喘息時段） |
| 15:00 | 影印室 | 周以澄 | 回馬槍 |
| 17:30 | 下班前的會議室 | 好感度較高者 | 突襲＋回馬槍組合（最終關） |

每個時段的流程：
1. 場景切入，時鐘（打卡單）前進到該時段。
2. 對話推進（點擊、Enter 或 Space）。
3. 出現 2–3 個選項，選完加減好感度。
4. 在劇本指定的時機觸發主管事件，打斷對話，進入小遊戲。
5. 小遊戲結果：成功就接回對話（可能有額外的心動台詞），失敗就播放搞笑被抓小劇場，懷疑值 +1，再接回對話。

## 5. 系統

### 5.1 好感度
- 每位男角一個整數，範圍 0–100，起始 20。
- 選項影響：−10 到 +15。小遊戲成功後的心動台詞 +5。
- 介面上**不顯示大型數值條**。改成在對話視窗的男角名字旁顯示訊息狀態：「未讀」→「已讀」→「已讀・對方輸入中…」（三段門檻：<40、40–69、≥70）。數值本身只在除錯模式顯示。

### 5.2 懷疑值
- 整數 0–3，起始 0。
- 掩護失敗（沒有掩護或時機錯誤）就 +1，並播放被抓小劇場。
- 到 3 立刻進入**被抓結局**。
- 介面上用打卡單上的「主管約談」蓋章格表示，蓋滿 3 格就結束。

### 5.3 預判主管（小遊戲）

**畫面：** PixiJS 畫一條俯視的辦公室走道，女主的位置固定，主管從畫面一側沿路徑移動，前方有一個扇形視線範圍。

**操作：**
- **按 Space（或點「掩護」）**：進入掩護，持續 2.0 秒，之後冷卻 1.0 秒。
- **按 1 / 2 / 3（或點選）**：選擇掩護方式：假裝影印、講電話、蹲下撿筆。預設是上一次用過的方式。
- 每個事件約 3–7 秒；17:30 的組合關約 9 秒。按下「準備好了」後才開始計時，玩家有時間讀提示。

**判定：** 主管視線掃到女主的那一刻：
| 狀態 | 結果 |
| --- | --- |
| 正在掩護，而且掩護方式符合現場 | **成功**：接回對話，男角給一句心動台詞（好感 +5）。 |
| 正在掩護，但方式不符合現場（例如在茶水間假裝影印） | **尷尬過關**：主管停下來碎念一句，懷疑值不變，該男角好感 −5（氣氛被打斷）。 |
| 沒有掩護（太早按導致已經結束，或根本沒按） | **被抓**：懷疑值 +1，播放被抓小劇場。 |

**三種模式：**
| 模式 | 行為 | 玩家要學的事 |
| --- | --- | --- |
| **巡邏** | 固定路線、固定速度，路線事先畫在地上。 | 看路線，算時機。 |
| **突襲** | 開頭 0.8 秒的預兆（文字「啪嗒、啪嗒……」加上「一股茶葉蛋味飄來」），然後高速衝進來。 | 看到預兆立刻反應。 |
| **回馬槍** | 走到門口假裝離開，停 1.0–1.5 秒，再轉身回來。 | 不要太早放鬆；掩護時間只有 2 秒，太早按會在他回頭時剛好結束。 |

**每個場景合適的掩護方式：** 寫在劇本資料裡（例如茶水間＝講電話，影印室＝假裝影印），並在場景畫面中放道具做提示（影印機、電話、地上的筆）。

**難度參數**（全部放在一個設定檔，方便試玩後調整）：主管速度、預兆長度、回馬槍停頓時間、掩護持續時間、冷卻時間。

**減少動態效果（`prefers-reduced-motion`）：** 主管改成一格一格跳動，預兆改成靜態提示，判定時間放寬 20%。

### 5.4 結局
判定順序：
1. 任何時候懷疑值到 3 → **被抓結局**：賈正經把女主叫進辦公室，以為她在搞副業，最後竟然要她「把那個副業的企劃也寫一份給我」。
2. 撐到 18:00 → **平安下班**：好感度較高的男角出現在電梯口。同分的話由 17:30 時段的選擇決定。

結局以「簽核單」卡片呈現，蓋上「核准」或「退件」的章，並列出今天的結果（兩位男角的狀態、被約談次數）。

## 6. 技術架構

**技術：** Vite + Vue 3 + TypeScript + Pinia + PixiJS v8；測試用 Vitest 與 Playwright。

```
office-romance/
├─ index.html
├─ src/
│  ├─ main.ts
│  ├─ App.vue                  # 16:9 舞台：底層 Pixi 畫布，上層 Vue UI
│  ├─ game/                    # 純 TS 遊戲邏輯，不可 import Vue 或 Pixi
│  │  ├─ types.ts              # 劇本節點、選項、效果、主管事件的型別
│  │  ├─ director.ts           # 狀態機：時段 → 對話 → 選項 → 主管事件 → 結局
│  │  ├─ affection.ts
│  │  ├─ suspicion.ts
│  │  ├─ boss.ts               # 三種模式的移動與視線時間軸、判定
│  │  ├─ tuning.ts             # 難度參數
│  │  └─ rng.ts                # 可指定種子的亂數，測試用
│  ├─ content/
│  │  └─ day1.ts               # 第一天劇本（型別化資料）
│  ├─ stores/
│  │  └─ game.ts               # Pinia：唯一的狀態來源，包裝 director
│  ├─ scenes/                  # PixiJS
│  │  ├─ stage.ts              # 建立 Application、縮放
│  │  ├─ officeScene.ts        # 背景與佔位角色
│  │  └─ bossMinigame.ts       # 走道、主管、視線
│  ├─ ui/                      # Vue 元件
│  │  ├─ DialogueWindow.vue    # 通訊軟體視窗樣式的對話框
│  │  ├─ ChoiceNotes.vue       # 便利貼選項
│  │  ├─ ClockSheet.vue        # 打卡單時鐘與約談章
│  │  ├─ BossAlert.vue         # 會議邀請樣式的主管警報、掩護按鈕
│  │  ├─ CoverPicker.vue
│  │  └─ EndingCard.vue        # 簽核單結局
│  ├─ bus.ts                   # Pixi 與 Vue 之間的小型事件匯流排
│  └─ styles/tokens.css
└─ tests/
   ├─ unit/                    # Vitest
   └─ e2e/                     # Playwright
```

**資料流：** Pinia store 持有全部狀態並呼叫 `game/director`。Vue 元件只讀 store、送出玩家動作。Pixi 場景訂閱 store 的變化來繪圖，小遊戲的輸入與判定結果透過 `bus.ts` 回報給 store。`game/` 不知道 Vue 和 Pixi 的存在，所以可以單獨測試。

**畫面：** 邏輯解析度 1280×720，依視窗等比縮放，四周補底色。目標平台是電腦瀏覽器（Chrome、Edge、Safari 最新版），最小視窗寬度 1024px。

## 7. 指令

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 開發伺服器 |
| `npm run build` | 型別檢查加正式建置 |
| `npm run preview` | 預覽正式建置 |
| `npm run test` | Vitest 單元測試 |
| `npm run test:e2e` | Playwright 冒煙測試 |
| `npm run lint` | ESLint 加 Prettier 檢查 |

除錯參數：網址加 `?debug=1` 顯示好感度數值與判定線；`?seed=123` 固定亂數；`?slot=3` 直接跳到指定時段。

## 8. 測試策略

- **單元測試（Vitest，`src/game/*`）：**
  - 好感度與懷疑值的上下限、門檻。
  - 三種主管模式的時間軸：在已知種子下，視線掃到女主的時間點正確。
  - 判定表的每一格（成功、尷尬過關、被抓），包含「太早按導致掩護結束」與回馬槍的情況。
  - 結局判定：懷疑值 3、同分、各男角勝出。
  - 劇本資料檢查：每個節點都接得到下一個、沒有斷掉的跳轉、每個主管事件都有合適的掩護方式。
- **冒煙測試（Playwright）：** 用 `?seed=` 跑完整一天，走一次平安下班、一次被抓，確認結局卡出現，主控台沒有錯誤。
- **人工檢查：** 只用鍵盤玩完一輪；開啟減少動態效果後玩完一輪；1024、1280、1920 寬度截圖。

## 9. 界線

- **一定要做：** `game/` 的邏輯都有測試；所有操作都能用鍵盤完成；支援減少動態效果；難度參數集中在 `tuning.ts`。
- **先問再做：** 新增依賴套件；任何美術或生圖流程；改動角色設定或主管的分寸。
- **不做：** 明確成人內容；Three.js；存檔與多日劇情（MVP 階段）。

## 10. 實作順序與進度

1. ✅ 建立 Vite + Vue + TS 專案，設定 Pinia、Vitest、ESLint、Prettier、Playwright。
2. ✅ `game/` 邏輯與單元測試（45 個測試）。
3. ✅ 小遊戲：俯視走道、扇形視線、掩護計時環。
4. ✅ 依 [ui-direction.md](design/ui-direction.md) 做 Vue UI。
5. ✅ 寫完 `content/day1.ts` 的全部劇情。
6. ✅ 視覺檢查：截圖並修正版面（1920 寬度只檢查了標題畫面）。
7. ⬜ 美術：角色設定圖與表情，見 [art/plan.md](art/plan.md)。
8. ⬜ 找朋友試玩，依回饋調整 `src/game/tuning.ts`。
